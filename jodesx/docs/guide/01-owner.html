How a change reaches the live website

1. EditA file is changed on GitHub
2. Save“Commit” to the main branch
3. BuildVercel notices and rebuilds the site (≈1 min)
4. CheckIf the build succeeds, the new version goes live

If a change contains a mistake, Vercel's build fails safely: the old version stays online and nothing breaks for visitors. You simply fix the mistake and save again.

A3 Words you will see

Repository (repo)
The folder on GitHub holding all website files. Yours is abood2891996/Skill; the website lives in its jodesx folder.
Commit
Saving a change on GitHub, with a short note describing it. Every commit is kept, so changes can be undone.
Branch / main
A version line of the files. main is the one that goes live. Always save your edits to main.
Deployment
One published version of the website on Vercel. Each commit creates a new deployment.
Build
Vercel turning the files into a website. Takes about a minute. It can “fail” if a file has a mistake.
Domain
Your address: jodesx.com.
DNS records
Settings that tell the internet where your website and email live. Yours are managed in Vercel.
Environment variables
Private settings stored in Vercel (like your Resend key and inbox address) that the website reads. They are not in the files on GitHub.
API key
A password that lets one service use another (e.g. the website using Resend). Never share it.
Redeploy
Asking Vercel to rebuild the current version — needed after changing environment variables.

A4 Editing text on the website yourself

Almost all words on the website are stored in a few “content” files. You can edit them directly on the GitHub website — no software needed.

Step by step: change any text

  1. Go to github.com, sign in, and open the repository abood2891996/Skill.
  2. Make sure the branch selector at the top-left says main.
  3. Open the folders jodesx → src → content (or the file named in the table below).
  4. Tap the file, then tap the pencil icon ✎ (“Edit this file”) at the top-right of the file.
  5. Find the text with your browser's search (on iPad: Share → Find on Page; on a computer: Ctrl/Cmd + F) and change only the words between the quote marks.
  6. Tap Commit changes…, write a short note such as “Update homepage headline”, choose Commit directly to the main branch, and confirm.
  7. Wait about one minute, then refresh your website.

The three golden rules when editing text files

  • Change only what is inside the quote marks "like this". Keep the quotes, commas and brackets exactly as they are.
  • If your text contains a double quote ", use typographic quotes “ ” instead.
  • Apostrophes (’) are fine inside "…" text in .ts files.

A5 Posting, closing and removing jobs

Each job is one small text file in jodesx/src/content/jobs/. The website builds the job board, the job page, the application form, the sitemap entry and Google Jobs data from it automatically.

Post a new job

  1. On GitHub (branch main), open jodesx/src/content/jobs/ and open _TEMPLATE.md. Tap the copy icon to copy its contents.
  2. Go back to the jobs folder and tap Add file → Create new file.
  3. Name it after the job with lowercase letters and hyphens, ending in .md — e.g. customer-support-agent.md. This becomes the address www.jodesx.com/careers/customer-support-agent.
  4. Paste the template and fill in the fields at the top (between the two --- lines) using the table below.
  5. Write the description under the second --- line.
  6. Tap Commit changes → main. After about a minute the job appears on /careers.

Writing the description

You can use exactly four formats:

  • ## Heading — a section title
  • - item — a bullet point
  • **bold** — bold words
  • An empty line — starts a new paragraph
---
title: Customer Support Agent
team: Customer Support
type: Full-time
workplace: Remote
location: Jordan
status: open
posted: 2027-01-15
summary: Answer customers by email and chat for international brands.
---

Short opening paragraph about the role.

## What you'll do

- Answer customer emails
- **Resolve** issues within agreed rules

Close or remove a job

  • Close (stop applications, keep the page): edit the file and change status: open to status: closed. It disappears from the job board; the server refuses new applications.
  • Remove completely: open the file, tap the ⋯ menu → Delete file, then commit to main.

When no jobs are open, the Careers page automatically shows “No open roles right now” and invites open applications.

If the job does not appear after 2 minutes, a field probably has a value that is not allowed (for example full time instead of Full-time). Open Vercel → Deployments; the newest one shows Error. Tap it → Building logs: the message names the file and the field, e.g. team must be one of: …. Fix it and commit again. The live site is unaffected meanwhile.

  • Job applications arrive with the subject “Application APP-XXXXXX: Role — Name” and the CV attached. Reply goes to the candidate.
  • The reference code (JDX-… / APP-…) is also shown to the visitor, so you can match messages if they contact you.

Change which inbox receives them

  1. Vercel → project skill-dawz → Settings → Environment Variables.
  2. Find CONTACT_TO_EMAIL (inquiries) or CAREERS_TO_EMAIL (applications), tap ⋯ → Edit, change the address, Save.
  3. Go to Deployments → ⋯ on the top deployment → Redeploy. Changes only apply after a redeploy.

  1. Vercel → skill-dawz → Deployments.

  3. Tap ⋯ next to it → Instant Rollback (sometimes labelled Promote to Production) → confirm.

A9 Email: Zoho and Resend

  • Zoho Mail holds your mailboxes. Create more addresses (e.g. careers@jodesx.com) in Zoho's Admin Console → Users or as aliases of an existing mailbox. If you add one for applications, put it in CAREERS_TO_EMAIL and redeploy.
  • Resend only sends the website's emails. Its Emails page lists every email the website sent, with status Delivered, Bounced etc. — the first place to look if an inquiry seems missing.
  • Job applications are kept for 6 months, then deleted — this is what the privacy policy promises. In Zoho, a filter moves every email whose subject starts with Application APP- into a folder Applications. Once a month, open that folder, search for emails older than 6 months, delete them, then empty Trash. Candidates you hire: save their documents in their employee file before deleting.
  • Resend's free plan has sending limits (see resend.com/pricing). They are far above what a company website needs; upgrade only if Resend warns you.

If your Resend key is ever exposed (sent in a chat, pasted somewhere public): Resend → API Keys → delete it → create a new one → paste it into RESEND_API_KEY in Vercel → Redeploy.

A10 Google Search Console

Ownership of https://www.jodesx.com is verified through a tag in the website's code (do not remove it). The sitemap sitemap.xml is submitted and updates itself whenever pages or jobs change.

  • Performance — searches that showed your site, clicks and positions (data appears after a few days).
  • Pages — which pages Google has indexed and any problems.
  • URL inspection — paste a page address and tap Request indexing after a big change or a new job post.

A12 Security checklist

  • Two-factor authentication (2FA) on GitHub, Vercel, Zoho, Resend, Google, and the company holding your domain.
  • Domain auto-renew on, with a valid payment card.
  • Never share API keys or passwords in chats or emails; if one leaks, replace it (A9).
  • Only give GitHub/Vercel access to developers you trust, and remove it when their work ends (GitHub → Settings → Collaborators; Vercel → Team Settings → Members).
  • Keep this guide and a list of your accounts in a safe place.
