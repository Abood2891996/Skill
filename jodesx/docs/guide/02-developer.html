B3 Architecture

Rendering

  • Every page is statically prerendered at build time. Only /api/contact and /api/careers/apply run on the server (Node runtime).
  • Job pages use generateStaticParams with dynamicParams = false: a job exists only if its Markdown file existed at build time.
  • app/template.tsx wraps routes in RouteTransition, which fades content in only on client-side navigations. Never fade the first paint from opacity 0 — Chrome then records no LCP (this bug was found and fixed).

Content model (src/content/)

types.tsServiceSlug union, Service, BlueprintStage, Faq, TextBlock. Adding a slug makes TypeScript flag every place that must handle it.
services.tsFive Service objects: hero, problems, capabilities, workflow (feeds the Operations Blueprint), quality, use cases, engagement, FAQs, CTA, SEO meta. Exports services, getService().
pages.tsHome, About, process steps, engagement flow, challenge selector entries, quality loop, environments, engagement models, comparison rows, general FAQs.
why.tsWhy JoDesx: hero, core/more reasons, comparison table, commitments.
careers.tsCareers copy, reasons to join (with icon keys), traits, hiring steps, FAQs.
navigation.tsHeader and footer links (service links derived from services).
site.tsName, canonical URL (NEXT_PUBLIC_SITE_URL, default https://www.jodesx.com), public email, absoluteUrl().
jobs/*.mdJob postings (front matter + limited Markdown). Files starting with _ are ignored.

B4 Design system

  • Tokens — src/styles/tokens.css: palette (Midnight Navy #0B1220, Signal Cyan #35D6E8, Digital Violet #786BFF, Slate Blue #172438, Soft White #F4F7FB, plus shades), fluid type scale, spacing, radius hierarchy, motion curves. Exposed to Tailwind in globals.css via @theme inline (e.g. bg-navy-900, text-cyan-300, ease-signal).
  • Surfaces — .surface-dark / .surface-light set contextual variables (--fg, --fg-muted, --line, --accent, --signal, --focus…). Components use text-fg, border-line, text-accent-text etc., so they work on any surface. Prefer contextual classes over raw colours.
  • Type roles — .type-display-xl|lg|md (condensed width axis), .type-title, .type-lead, .type-small.
  • Controls — .btn .btn-primary|secondary .btn-sm, .link-signal, .panel, .form-control, .field-error.
  • Signal motion — signal.css. Every animation has a reduced-motion still frame.
  • Brand rules — see docs/BRAND-GUIDELINES.md. Sentence case; no all-caps eyebrows; numbered markers only for real sequences.

Change the brand colours: edit hex values in tokens.css only. Change the font: replace the file in src/app/fonts/ and the localFont call in app/layout.tsx; keep the --font-instrument variable name or update globals.css. The OG images load the .woff files in the same folder.

B5 Recipe: add a new page

  1. Create src/app/partners/page.tsx (folder name = URL):
import { ClosingCta } from "@/components/sections/ClosingCta";
import { PageHero } from "@/components/sections/PageHero";
import { JsonLd } from "@/components/ui/JsonLd";
import { Section, SectionHeader } from "@/components/ui/Section";
import { createMetadata } from "@/lib/seo/metadata";
import { breadcrumbJsonLd } from "@/lib/seo/structured-data";

export const metadata = createMetadata({
  title: "Partners",
  description: "One-sentence description for Google (150–160 characters).",
  path: "/partners",
});

const crumbs = [{ name: "Home", path: "/" }, { name: "Partners", path: "/partners" }];

export default function PartnersPage() {
  return (
    <>
      <PageHero crumbs={crumbs} title="Headline" lead="Supporting sentence." />
      <Section surface="light" labelledBy="intro-title">
        <SectionHeader id="intro-title" title="Section title" size="md" />
        <p className="mt-6 prose-measure text-fg-muted">Body text.</p>
      </Section>
      <ClosingCta title="Closing line." body="What to do next." />
      <JsonLd data={breadcrumbJsonLd(crumbs)} />
    </>
  );
}
  1. Add it to the menu/footer in src/content/navigation.ts.
  2. Add it to src/app/sitemap.ts.
  3. Add the route to the page lists in qa/interactions.cjs (link check) and run npm run check.

Rules: exactly one h1 (PageHero provides it); every Section gets a labelledBy that matches a heading id; alternate surfaces for rhythm (dark hero → light → paper …).

B6 Recipe: add another service

  1. src/content/types.ts — add the slug to ServiceSlug, e.g. | "sales-support" (Call Center was added this way). Run npm run typecheck: TypeScript now lists every place that must be updated.
  2. src/content/services.ts — create the Service object (copy an existing one) and add it to the services array. Navigation, grid, Blueprint tabs, comparison table columns and related links pick it up automatically.
  3. src/components/services/ServiceGlyph.tsx — add a glyph to GLYPHS (48-unit grid; lanes, gates, a .glyph-unit square).
  4. src/content/pages.ts — add a value for the new slug in every comparisonRows row (required by type); optionally add challenges and environments entries.
  5. src/lib/validation/contact.ts — add it to serviceOptions (form dropdown + email label).
  6. Create src/app/services/sales-support/page.tsx and opengraph-image.tsx by copying an existing service folder and changing the slug.
  7. Optional: add a job team in src/lib/careers/job-schema.ts (jobTeams).
  8. Run npm run check and the browser suite; check the Blueprint layout (it is designed for five stages per service).

B7 Recipe: change a form

Both forms follow the same pattern: schema → client form → API route → email text. Example — add a “Website” field to the inquiry form:

  1. src/lib/validation/contact.ts — add to contactSchema: 
    companyWebsite: z.string().trim().max(200).optional()
  .transform((v) => (v ? v : undefined))
  .pipe(z.url({ protocol: /^https?$/ }).optional()),
  2. src/components/forms/ContactForm.tsx — add companyWebsite: "" to EMPTY and the Values type, map it in toInput(), and render a <Field> + <TextInput> like the others.
  3. src/lib/contact/delivery.ts — include it in formatInquiryText() and the webhook payload.
  4. Add a unit test in tests/contact.test.ts; run npm run check.

The API route validates with the same schema, so no route change is needed for simple fields. Job applications use lib/validation/application.ts, careers/ApplicationForm.tsx and app/api/careers/apply/route.ts (multipart; read fields via form.get()).

B8 APIs, delivery and security

POST /api/contact (JSON) and POST /api/careers/apply (multipart)

Delivery provider error502
Delivered200 + reference (JDX-… / APP-…)
  • Delivery — lib/contact/delivery.ts, deliverMessage(). Webhook (HMAC-SHA256 in X-JoDesx-Signature) takes precedence over Resend. Applications fall back to the contact channel when CAREERS_* are unset.
  • Rate limiter — in-memory and per serverless instance (best effort). For stronger guarantees implement the RateLimiter interface with Upstash Redis or add a Vercel Firewall rule on the two API paths.
  • Security headers / CSP — next.config.ts. default-src 'self'; no third-party origins. Adding analytics, chat widgets, maps, fonts or CAPTCHA requires extending script-src/connect-src/frame-src for those origins and updating the privacy policy (cookies!). Vercel Web Analytics is same-origin and works without CSP changes.
  • 'unsafe-inline' in script-src (deliberate) — Next.js injects inline bootstrap scripts. The alternative, a per-request nonce via proxy.ts, would make every page dynamic (slower, higher hosting cost). Accepted because the site renders no user-supplied HTML (job Markdown is rendered as React elements, JSON-LD is escaped) and external scripts remain blocked. Revisit if a login, dashboard or user-generated content is added. securityheaders.com grade: A.
  • CORS — Access-Control-Allow-Origin is set to the site's own origin (Vercel's default is *).
  • Secrets live only in Vercel environment variables. Never prefix secrets with NEXT_PUBLIC_.
  • Runtime file access — the careers API reads src/content/jobs at runtime; outputFileTracingIncludes in next.config.ts ships those files with the function. Keep it if you move the folder.

B9 Careers internals

  • lib/careers/markdown.ts — tiny parser: front matter (key: value, quotes, trailing # comments) and body blocks (heading, list, paragraph, bold). Output is data rendered by careers/JobBody.tsx as React elements — no HTML injection path. Extend it there if posts need links or numbered lists.
  • lib/careers/job-schema.ts — Zod contract for front matter; build fails with a readable message on invalid posts.
  • lib/careers/jobs.ts — reads, validates, sorts (open first, newest first), caches in production.
  • app/careers/[slug]/page.tsx — job page; publishes JobPosting JSON-LD for open roles (Google Jobs). Remote roles use TELECOMMUTE with Jordan as applicant location — adjust in jobPostingJsonLd() if hiring elsewhere.

B11 Brand assets

All logo files in public/brand/, plus src/app/icon.svg and src/components/brand/logo-geometry.ts, are generated by scripts/build-brand.mjs from one geometric definition (48-unit grid) and an outlined wordmark (opentype.js). Change geometry there, run npm run brand:build, then node scripts/export-brand-png.cjs for PNGs. Never hand-edit the outputs.

B13 Gotchas learned while building

  • Fixed elements inside transformed parents — any transform/translate on an ancestor becomes the containing block. Keep overlays outside the header.
  • LCP — never start first-load content at opacity: 0.
  • CSP + Zod — keep z.config({ jitless: true }) in schema files; otherwise Zod probes eval and triggers CSP violations.
  • Grid rows stretch — form fields use content-start so a neighbour's hint or error does not push inputs out of line.
  • Apostrophes in JSX text — use &rsquo; (lint rule react/no-unescaped-entities).
  • NEXT_PUBLIC_* variables are inlined at build: change → redeploy.
  • Restarting a local production server after a rebuild: stop the old next-server process first, or it serves stale chunks (500s).
  • Vercel body limit — 4.5 MB per request; the CV cap (4 MB) stays below it.

B14 Maintenance

  • Monthly: npm outdated; apply patch/minor updates, run npm run check and the browser suite, deploy via PR.
  • Major upgrades (Next, React, Tailwind, Zod): read the official upgrade guides; upgrade one at a time on a branch; check the Vercel preview.
  • Security: npm audit; rotate the Resend key if exposed; review GitHub/Vercel access yearly.
  • Docs: keep jodesx/docs/ current — especially PROJECT-STATUS.md — and rebuild this guide with node scripts/build-guide.cjs.

Content rules that protect the brand

  • No invented clients, testimonials, statistics, certifications, awards or history — add proof only when it is real and approved.
  • JoDesx does not build AI models; say so where AI is mentioned.
  • Plain, specific, sentence-case copy; no “world-class”, “cutting-edge”, “seamless”.

Before you change anything important

  • Know how to roll back (A7).
  • Screenshot DNS records before touching them (A8).
  • Run npm run check (developers).
  • Test a form submission after changing email settings.
